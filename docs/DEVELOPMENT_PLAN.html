轻量智能 Agent 工具编排框架

从零开发设计方案 · 统一工程形式（分层 + 三件套 + 可插拔 + YAML 选型）· 2026-09-04

设计前提：现有项目文件一律视为示例 / 占位，全部重新设计开发。采用统一的工程形式：分层流水线（P0→P6）、每层「抽象基类 + 注册表 + @register 实现」三件套、config/settings.yaml 的选型字段、环境变量深路径覆盖、统一异常基类、tests 与模块一一对应。

一、设计总则（统一工程形式）

统一工程形式本项目落地
分层流水线（P0 公共 → P5 API → P6 部署）P0 公共 → P1 工具 → P2 记忆 → P3 LLM → P4 Agent/规划 → P5 会话/API → P6 部署
每层三件套：base.py（抽象基类+数据类）+ registry.py（Registry 实例）+ 实现类（@registry.register("name")）tool / memory / llm_client / planner 四层全部采用三件套
通用泛型 Registry[T]（src/common/registry.py）复用同一份 Registry，注册/查询/创建/类型校验/默认实现
异常体系：XxxEngineError 基类 + 各层子异常AgentFrameworkError + ToolError / MemoryError / LLMError / PlannerError / AgentError / SessionError / ConfigError / RegistryError
配置：settings.yaml + logging.yaml；${ENV} 注入；AGENT_ 前缀环境变量覆盖AGENT_ 前缀 + 双下划线分层覆盖（如 AGENT_LLM__MODEL）
每层 __init__.py 提供 build_xxx() 工厂 + 导入实现触发注册build_tool_registry() / build_memory() / build_llm_client() / build_planner()
API 层：main（create_app 工厂）+ dependencies + schemas + service + routes/完全一致，routes 拆 chat / tools / system
tests 与模块一一对应，examples 可运行，Docker 多阶段 + 非 root + healthcheck完全一致

三、开发步骤（Phase 0 → 6）

Phase 0P0 公共基础设施（约 0.5–1 天）

目标：搭建统一可插拔的地基，后续所有层依赖它。

  • src/common/constants.py：PROJECT_ROOT / DEFAULT_CONFIG_PATH / ENV_PREFIX="AGENT_" / APP_NAME
  • src/common/exceptions.py：AgentFrameworkError + ConfigError / RegistryError / ToolError / MemoryError / LLMError / PlannerError / AgentError / SessionError
  • src/common/registry.py：自研泛型 Registry[T]（register / has / names / get / create / set_default / 类型校验 / 重复注册拦截）
  • src/utils/config_loader.py：YAML → ${ENV} 展开 → AGENT_ 前缀深路径覆盖
  • src/utils/logger.py：setup_logging + get_logger（dictConfig 加载 logging.yaml）
  • src/utils/json_parser.py：LLM 输出 JSON 容错清洗
  • config/settings.yaml + config/logging.yaml

验证：test_registry / test_config / test_logger / test_exceptions 全绿。

Phase 1P1 工具层：可插拔注册中心 + 参数校验（约 1–1.5 天）

目标：落地需求①「通用工具注册中心（天气/检索/计算器/时间可插拔注册）」。

  • tool/base.py：BaseTool 抽象 + ToolResult 数据类 + ToolSchema（JSON Schema 形态）
  • tool/registry.py：tool_registry = Registry("tool", base_type=BaseTool)
  • tool/validator.py：执行前按 JSON Schema 参数校验，失败抛 ToolError（供 Agent 自愈）
  • 四个实现：calc_tool（ast 白名单安全计算）、time_tool、weather_tool、kb_search_tool（先 mock 后可接真实 API）
  • tool/__init__.py：导入实现触发注册 + build_tool_registry() 工厂 + 统一 run 入口（含校验）

验证：test_tool 覆盖注册 / 参数校验 / 执行 / 未注册报错。

Phase 2P2 记忆层：短时 + 长时双缓存（约 1 天）

目标：落地需求③「短时 + 长时双缓存记忆机制」。

  • memory/base.py：BaseMemory 抽象 + Message
  • memory/registry.py：memory_registry
  • in_memory_memory.py：@register("in_memory") 进程内 dict + 滑动窗口（保留最近 N 条）
  • redis_memory.py：@register("redis") 每会话 key + JSON 序列化 + TTL
  • memory/__init__.py：build_memory() 按配置选型；双缓存组合（短时快速读写 + 长时兜底恢复的冷热分层）

验证：test_memory 覆盖写入/读取/滑动窗口/清空/双缓存恢复。

Phase 3P3 LLM 客户端层（约 0.5–1 天）

目标：为 Agent / 规划器提供统一 LLM 入口。

  • llm_client/base.py：BaseLLMClient（chat 返回文本 + generate_json 返回结构化 JSON）
  • llm_client/registry.py：llm_client_registry
  • openai_client.py：@register("openai_compatible")，base_url 可配 → 兼容豆包 / DeepSeek / OpenAI
  • fake_client.py：@register("fake")，可预设响应序列，驱动循环测试与无 key 演示
  • llm_client/__init__.py：build_llm_client() 工厂

验证：test_llm_client（fake 返回序列 / openai 用 mock 拦截）。

Phase 4P4 Agent 核心：规划 + ReAct + 容错策略（约 1.5–2 天）

目标：落地需求②「LLM 自动任务拆解 / 多步规划 / 自动选择工具」与⑤「异常重试 / 参数自动修正 / 失败兜底」。

  • planner/base.py：BasePlanner + PlanStep（task / depends / tool_hint）
  • planner/llm_planner.py：@register("llm")，让 LLM 把用户请求拆解为多步计划
  • agent/base.py：BaseAgent + AgentOutput（success / content / steps / tool_calls）
  • agent/react_agent.py：@register("react") ReAct 循环——思考→选工具→执行→回填，直到 finish；含 max_loop 保护
  • agent/policy.py：容错策略——瞬时失败退避重试；参数校验失败回喂 LLM 重新生成（限次）；工具不存在/执行异常引导换工具或兜底答案
  • agent/__init__.py：build_agent() 工厂

验证：test_planner / test_agent——多步任务端到端跑通 + 注入错参数/假工具名可自愈或优雅降级。

Phase 5P5 会话层 + API 层（约 1 天）

目标：落地需求④「会话状态持久化，支持多轮连续任务」并对外服务化。

  • session/manager.py：SessionManager（create / load / clear，会话数据落 memory 持久化）
  • api/schemas.py：ChatRequest（session_id / query）/ ChatResponse（answer / steps / tool_calls）/ ToolsResponse / HealthResponse
  • api/service.py：AgentService——懒加载 registry / memory / llm / planner / agent，多轮会话编排
  • api/main.py + dependencies.py + routes/（chat / tools / system）

验证：test_session / test_api——HTTP 多轮连续对话返回正确，重启后会话可恢复。

Phase 6P6 示例 + 部署 + 文档（约 0.5–1 天）

目标：可交付、可演示、可扩展。

  • examples/run_agent_demo.py：CLI 交互式多轮 demo
  • Dockerfile（多阶段构建 + 非 root + healthcheck）+ docker-compose.yml（app + redis）
  • docs/architecture.svg + README 重写（架构 / 快速开始 / API / 可插拔扩展指南 / 测试）
  • 可插拔演示：新增一个工具一行 @register 即生效

验证：docker compose up 一键起服务；README 按步骤可复现。

五、关键设计决策（答辩加分点）

  • 可插拔是灵魂：四层（tool/memory/llm_client/planner）统一 Registry，新增实现只写类 + 一行装饰器，上层零改动。
  • 安全计算器：禁用 eval，用 ast.parse 白名单校验表达式。
  • 双缓存冷热分层：短时（进程内/秒级）+ 长时（Redis/跨重启），体现「有状态、有记忆」。
  • 参数校验前置 + 自愈：执行前 JSON Schema 校验，校验失败把结构化错误回喂 LLM 重新生成参数（限次）。
  • 容错策略独立成模块：policy.py 把重试/修正/兜底从 Agent 主循环解耦，可插拔、可单测。
  • FakeLLM 贯穿开发：无 API key 也能驱动全链路测试与演示，CI 友好。
  • 配置驱动选型：settings.yaml 的 name 字段 + AGENT_ 环境变量覆盖，容器化/多环境零改动。
