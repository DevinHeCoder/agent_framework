# 性能优化方案汇总（2026-10 两轮）

> 目标：让"简单计算 / 时间 / 天气 / 知识库检索 / 确定性复合任务"秒级返回，
> 同时不破坏原有工具调度、多工具任务、多轮记忆等核心行为。
> 所有改动均本地验证（全量回归 205 passed / 1 skipped），未直接改服务器。

---

## 一、结论：适用范围

**不是示例专用，而是"形态通用"。** 三条优化路径的适用范围：

| 路径 | 适用范围 | 不适用（自动回退 LLM） |
|---|---|---|
| 规则直配（零 LLM 规划） | 满足规则的**任意**简单查询（见 §2 形态表） | 闲聊、复杂/模糊表述、含函数调用的计算、非确定性复合任务 |
| 确定性直答（跳过回答 LLM） | 任意 calc/time/weather/kb_search 步骤**全部成功** | 任一工具失败，或含非确定性工具 |
| 通用执行优化（§3） | **所有** LLM 任务 | 无 |

---

## 二、第一层：规则直配（零 LLM 调用）

**核心思想**：确定性请求不需要 LLM 理解——用保守正则直接产出执行计划。
任何形态匹配失败 → `return None` → 回退原 LLM 规划（行为不变，仅 prompt 更小）。

修改文件：`src/planner/llm_planner.py`（新增 `_fast_plan_for()`、`_extract_weather_city()`、`_extract_calc_expr()`、`_extract_time_query()`）

### 1. 时间直配
- **匹配形态**：`现在几点/钟`、`当前时间`、`今天日期`、`几点啦` 等（正则：
  `(现在|当前|今天|此刻).*(几点|时间|日期)` 或 `(几点|时间|日期).*(现在|当前|今天)?$`）
- **产出**：`time` 工具 → 直答 `当前时间：YYYY-MM-DD HH:MM:SS`
- **命中示例**：`现在几点钟了？`、`现在几点`、`当前时间`
- **不命中**：`帮我看看时间安排`（无明确时间意图 → LLM）

### 2. 天气直配
- **匹配形态**：含天气关键词（天气/气温/温度/冷不冷/热不热/预报）+ 清洗前缀
  （请/帮我/查一下/查询/看看）、时间词（今天/现在/当前/实时/最新）、尾部短语
  （天气怎么样/冷不冷…）、"的"之后，**剩余 2-4 字整体即为城市名**。
- **产出**：`weather(city=城市名)` → 直答 `城市天气：X°C，…，湿度 Y%`
- **命中示例**：`帮我查一下杭州今天的天气`、`查一下北京天气`、`上海的天气怎么样`、`今天杭州热不热`
- **不命中**：`杭州有什么好吃的`（无天气词）、`北京市朝阳区的天气`（>4 字 → LLM）

### 3. 计算直配
- **匹配形态**：剥前缀（计算/算/算一下/算算/帮我算/帮我算一下）+ 剥后缀
  （等于多少/是多少/等于几/结果是多少/为多少）后，剩余为**纯表达式**
  （数字 + `+ - * / ( ) .`，`**` 幂运算含 `*` 可命中）。
- **产出**：`calc(expression)` → 直答 `计算结果：X = Y`
- **命中示例**：`请计算 (3+5)*2 等于多少`、`2**10等于多少`、`帮我算 100/4`
- **不命中**：`帮我算一下 2**10 的值是多少`（含"的值"）、`计算 abs(-8)`（函数调用 → LLM）

### 4. 知识库检索直配
- **匹配形态**：后缀式 `X？请检索知识库回答` / `帮我检索知识库回答 X`；
  冒号式 `检索知识库：X` / `帮我检索一下知识库，X`。
- **产出**：`kb_search(query=X)` → 直答引用式结果（带 doc_id）
- **命中示例**：`双缓存记忆机制是什么？请检索知识库回答`、`检索知识库：工具注册中心`
- **不命中**：`帮我检索知识库并算 1+1`（复合任务 → LLM）

### 5. 复合任务直配（"先 X 再 Y"）
- **匹配形态**：含 `再/然后/接着` 分隔符，且能分别拆出：
  - A 半 = 天气查询（`_extract_weather_city`）或时间查询（`_extract_time_query`）
  - B 半 = 纯计算表达式（`_extract_calc_expr`）
  任一子句拆解失败 → 回退 LLM。
- **产出**：`weather + calc` 或 `time + calc` 并行执行 → 拼接直答
- **命中示例**：`先查一下北京天气，再帮我算一下2**10`、`先查北京天气再算 2**10`
- **不命中**：`先查资料，再写报告`（无法拆出确定性子句 → LLM）

> **调试记录**（两轮中踩过的坑）：
> 1. 城市抽取把前缀"查一下"、时间词"今天"、"的"捕获进城市名 → 改为"清洗后剩余整体=城市"；
> 2. "现在几点"被天气规则误判（城市"几点"）→ 时间判定提前于天气；
> 3. "循环任务"（4 字无天气词）被误判城市 → 增加天气关键词门控；
> 4. 正则备选顺序 `(计算|算|算一下…)` 中"算"先于"算一下"匹配，剥掉"帮我算"后残留"一下" → 长词优先。

## 三、第二层：确定性直答（跳过第二次 LLM）

**核心思想**：calc/time/weather/kb_search 的结果确定性强，工具返回后直接拼成回答文本，
**不再让 LLM 润色**（省 1 次串行 LLM 调用）。

修改文件：`src/agent/react_agent.py`（新增 `_direct_answer_for_multi()`、扩展 `_direct_answer_for()`）

- **白名单**：`("calc", "time", "weather", "kb_search")`
- **单工具**：`calc → 计算结果：X = Y`；`time → 当前时间：…`；
  `weather → 城市天气：X°C，…`；`kb_search → 知识库检索结果：\n- [标题] 内容（doc_id=…）`
- **多工具**：所有步骤在**白名单内且全部成功** → 各步直答文本用 `；` 拼接；
  任一失败或含非确定性工具 → 回退 LLM 综合。
- **开关**：`agent.direct_answer`（settings.yaml），关闭后全部走 LLM。

**质量权衡**：kb 类回答从"LLM 润色综合"变为"检索片段引用式"——更接近 RAG 产品标准呈现、可溯源；
若需润色可关 `direct_answer`。

## 四、第三层：通用执行优化（对所有 LLM 任务生效）

| # | 优化 | 修改文件 | 修改内容 | 原因 | 效果 |
|---|------|----------|----------|------|------|
| 1 | 规划 prompt 瘦身 | `src/planner/llm_planner.py` | `_render_tools()` 不再输出完整 JSON Schema，改为 `名称 + 截断描述(48字) + 参数名:类型(必填*)` | 4 工具全量 Schema 约 1-2K tokens，长 prompt 拖慢模型输出（实测长 prompt 输出完整 JSON 要 2~7.6s，短 prompt 1.3s） | 规划输入大幅下降，输出更快 |
| 2 | 规划用快模型 | `src/planner/llm_planner.py` + `config/settings.yaml` | 新增 `plan_model` 参数透传，`planner.plan_model: ${AGENT_LLM_PLAN_MODEL:}`，.env 设 `qwen3.8-flash` | 规划只需结构化输出，用快模型不影响质量 | 规划 7.6s → 1.3~2s |
| 3 | LLM 直连（不走代理） | `src/llm_client/openai_compatible.py` + settings | `use_proxy` 参数；`httpx.Client(trust_env=False)` 直连；`llm.use_proxy: ${AGENT_LLM_USE_PROXY:false}` | 系统代理（127.0.0.1:7897）劫持 LLM 请求拖慢或失败 | 消除代理抖动；**2026-10-18 修复布尔字符串 bug**：env 展开的 `"false"` 是非空字符串为真值 → 实际仍走代理；在 `src/llm_client/__init__.py` 的 `_filter_ctor_kwargs` 增加 `_coerce_bool()` 归一化 |
| 4 | 历史窗口截断 | `src/agent/react_agent.py` | `_HISTORY_WINDOW = 10`，最终回答只携带最近 10 条历史 | 多轮会话后 prompt 无限膨胀拖慢响应 | 回答 prompt 长度可控 |
| 5 | 多工具并行 | `src/agent/react_agent.py` | `ThreadPoolExecutor(max_workers=min(len(tool_steps), 4))` 并行执行独立工具步骤，trace 按 step_id 排序 | 多工具步骤间无数据依赖 | 复合任务工具耗时从串行 → 并行 |
| 6 | plan 阶段 LLMError 兜底 | `src/agent/react_agent.py` | `except (PlannerError, LLMError)` → `build_fallback` | 规划时 LLM 网络异常原会直接 500 | 失败返回友好兜底，不崩接口 |

## 五、实测效果（真实模型 qwen3.8-max + flash 规划）

| 问题 | 优化前 | 优化后 | 关键 trace |
|------|--------|--------|------------|
| 请计算 (3+5)*2 等于多少 | 11~17s（6 次 LLM 调用截图） | **0.01~0.02s** | calc:success 零 LLM |
| 现在几点钟了？ | ~6.6s（2 次 LLM） | **0.00s** | time:success 零 LLM |
| 帮我查一下杭州今天的天气 | ~13s（2 次 LLM） | **0.00s** | weather:success 零 LLM |
| 先查北京天气再算 2**10 | 6~15s（2 次 LLM） | **0.03s** | weather+calc 并行 零 LLM |
| 双缓存记忆机制是什么？请检索知识库回答 | **17.5s**（2 次 LLM） | **0.00s** | kb_search:success 零 LLM |
| 你好，你是谁（闲聊） | 13s（2 次 LLM） | ~15s（2 次 LLM 直连） | respond:success（不走代理） |

> 说明：闲聊类无规则可命中，仍 2 次 LLM，延迟取决于模型本身与网络；
> 本机环境代理关闭时，直连链路是 LLM 可用的必要条件（见 §四-3 的 bug 修复）。
